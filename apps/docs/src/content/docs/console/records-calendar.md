## 发布记录

按**子任务**（内容 × 平台 × 账号）展示全部发布流水。一条内容发三个平台就有三行。

表格列：内容 / 语言 / 平台 / 状态 / 失败原因 / 时间 / 操作。

### 状态与对应动作

| 状态 | 含义 | 你要做什么 |
| --- | --- | --- |
| **队列中** | 已入队等待执行 | 等，通常几分钟 |
| **发布中** | worker 正在调用 Postiz | 等 |
| **已提交** | Postiz 已受理 | **不等于社媒发成功**，见下节 |
| **失败** | 发布失败，「失败原因」列有说明 | 点 **重试** |
| **待对账** | 结果未知（响应超时或中断） | 去平台**亲眼确认**，再点「确认已发送」或「确认未发送」 |

**运营只能看到自己账号相关的发布任务。**

### 处理失败

1. 看「失败原因」列 —— 系统会写明具体错误
2. 判断是**临时故障**还是**内容问题**：

| 失败原因类型 | 处理方式 |
| --- | --- |
| 网络超时、平台 5xx | 直接点 **重试** |
| 文案超长被拒 | 回内容详情改文案，再重试 |
| Instagram 缺图 | 补配图后重试 |
| 授权失效 / 401 | 去[账号健康](/console/accounts-routing/)重新绑定该账号 |
| 平台限流 | 等一段时间再重试 |

### 处理待对账（重要）

**待对账** = 系统调用 Postiz 时没收到响应，**不知道帖子到底发出去了没有**。

:::danger[必须人工去平台确认，不要猜]
系统**故意不自动重发**待对账任务 —— 万一其实已经发出去了，自动重发会造成**重复发帖**。

正确做法：
1. 打开对应社媒平台，**亲眼看**这条帖子在不在
2. 在 → 点 **确认已发送**
3. 不在 → 点 **确认未发送**（之后可以重试）
:::

## 投递对账说明

这是新人**最容易误解**的地方：

```
系统显示「已提交」  ≠  帖子已经在社媒上
     ↓
 只表示 Postiz 收下了任务
     ↓
 平台侧仍可能投递失败
```

系统每 **30 分钟**自动回读 Postiz 的帖子状态：

- 投递失败（`state=ERROR`）的帖子 → **自动回退为「失败」并解锁重试**
- 投递成功的不受影响

:::tip[「系统说发了但社媒上没有」]
先别急着重发。等一个对账周期（最多 30 分钟），系统会自己把它退回失败状态，
这时再点重试。手动重发有重复发帖的风险。
:::

**演练模式（DRY_RUN）下**，帖子只在 Postiz 生成草稿，社媒上一定看不到 —— 这是预期行为。

## 发布日历

按日期分组展示**已排期**和**近期已发布**的内容，**最新日期在最上面**。

- 每条显示时间、语言与状态
- 用 **Schedule** 模式提交的内容，在实际发布前就会出现在这里

### 用途

| 场景 | 怎么用 |
| --- | --- |
| 确认排期没排错 | 提交排期后来这页核对日期时间 |
| 检查某天发太密 | 看单日条目数，避免同一账号刷屏 |
| 回顾近期发了什么 | 按日期往下翻 |
