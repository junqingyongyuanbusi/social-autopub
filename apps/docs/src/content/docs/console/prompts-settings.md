## Prompt 管理

生成指令按版本管理，**已发布的版本不可变**。

### 版本模型

- 修改 Prompt 会**创建一个新版本**，而不是覆盖旧版本
- 通过「激活」指针决定当前生效版本，**可随时回滚**到任意历史版本
- 每个版本记录**变更说明**与激活时间

### 版本包含哪些配置

| 配置项 | 作用 |
| --- | --- |
| 系统提示词 | 生成任务的总体角色与约束 |
| 生成模板 | 首次生成用的模板 |
| 修订模板 | 重新生成用的模板 |
| 平台规则 | 各平台的格式与长度要求 |
| 类型语气 | 按内容类型（新闻/教育/测评/曝光）区分语气 |

### 改 Prompt 的纪律

1. 改之前**写清变更说明** —— 未来回滚时靠它判断该退到哪一版
2. 改完**先生成一两条看效果**，别直接批量跑
3. 效果不对就**回滚到上一个版本**，不要在坏版本上继续叠改

:::tip[能追溯生成质量变化的原因]
历史生成记录会**关联到当时使用的 Prompt 版本**。
运营反馈"最近文案变差了"，可以按时间对上是哪次 Prompt 变更导致的。
:::

## 设置

### Notion 数据源登记

把 Notion 数据库接进系统，每条登记对应一个轮询来源。

**新增步骤：**

1. 填 **Notion Database ID** —— 从 Notion 数据库链接里复制那 **32 位 ID**
2. 填 **语言** —— 如 `en`、`ja`、`id`（占位提示是 `en`）
3. 填 **表类型**
4. 点 **登记数据源**

**Database ID 怎么拿**：在浏览器打开 Notion 数据库，地址栏形如
`notion.so/工作区/<32位ID>?v=...`，中间那串 32 位字符就是。

**数据源列表**显示：Database ID / 语言 / 表类型 / **上次轮询** / 状态 / 操作。

| 操作 | 效果 |
| --- | --- |
| 启用 / 停用 | 停用后不再轮询，**已入库内容不受影响** |
| 删除 | 删除登记，**不影响已入库内容** |

:::caution[登记完还要在 Notion 侧授权]
Notion 集成必须被**邀请进该数据库**才读得到内容。
登记后「上次轮询」一直空白或状态异常，先检查 Notion 侧是否已把集成加为数据库的连接。
:::

### WikiFX API

这一区**只有说明和一个跳转按钮**，没有可填的字段。

WikiFX 热点 API 由 API 服务读取环境变量配置，**Key 不在此页面显示或编辑**。
页面也**故意不提供「已配置」状态** —— 避免把配置项存在误读为"连接真的通"。

想验证连接，点 **前往热点选题测试连接**，看 [热点选题](/console/topics/) 页能不能正常读到榜单。

### 数据源监控

轮询失败会记录失败尝试（`NotionIngestFailure`），可在页面查看与重试。

| 失败常见原因 | 怎么修 |
| --- | --- |
| 集成没被加进数据库 | 在 Notion 里把集成加为该数据库的连接 |
| Database ID 填错 | 核对 32 位 ID |
| 字段名不匹配 | 见 [Notion 接入 · 字段约定](/sources/notion/#字段约定) |
| Token 失效 | 找管理员更新 `NOTION_TOKEN` |

## 用户管理

在「设置」页下方，管理控制台的登录账号。

### 新建用户

1. 填 **邮箱**（登录用，必须唯一）
2. 填 **姓名**
3. 填 **初始密码** —— **至少 8 位**
4. 选 **角色**：**运营** 或 **管理员**
5. 点 **新建用户**

| 报错提示 | 原因 |
| --- | --- |
| 「请完整填写，密码至少 8 位」 | 有字段空着，或密码不足 8 位 |
| 「创建失败：邮箱可能已存在」 | 该邮箱已注册过 |

### 用户列表与操作

列表显示：姓名 / 邮箱 / 角色 / 创建时间 / 操作。

| 操作 | 说明 |
| --- | --- |
| **重置密码** | 弹框输入新密码（至少 8 位），成功后提示「已重置 <姓名> 的密码」 |
| **删除** | 弹确认框。**不能删除最后一个管理员**，会提示「删除失败：不能删除最后一个管理员」 |

### 新人入职的完整动作

新建用户**只是第一步**。光有账号，运营登录后页面基本是空的：

1. 在这里**新建用户**（角色选运营）
2. 去 [账号健康](/console/accounts-routing/#编辑台账仅管理员)，在对应账号的**授权用户**里勾上此人 → 保存
3. 确认该账号已设**市场**，且[路由矩阵](/console/accounts-routing/#路由矩阵)里有对应规则
4. 把 [提交给管理员的信息清单](/prepare/account-info/) 发给这个人，收集 Facebook ID 等信息
5. 把他加进 Meta 应用的[授权名单](/prepare/meta-developer/#把成员加入授权名单必做否则运营绑不上号)
6. 让他照 [新手上手](/prepare/first-post/) 自己绑号

:::caution[两个角色的区别]
| | 运营 | 管理员 |
| --- | --- | --- |
| 看到的账号与内容 | 只有被授权的 | 全部 |
| 路由矩阵 / Prompt / 设置 | **看不到** | 可见可改 |
| 立即同步账号、删除失联账号 | 不能 | 能 |
| 编辑账号台账 | 不能 | 能 |

管理员权限很大，**按需分配**。
:::
